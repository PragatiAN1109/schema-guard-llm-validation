01 / Problem

JSON Schema validation is not enough

LLMs produce structurally perfect JSON that is logically broken. Every example below passes jsonschema validation — and every one is wrong.

HC-003 · CRITICAL

Discharge before admission

Patient Sarah Mitchell discharged 7 days before her admission date. Structurally valid. Clinically impossible.

FN-002 · CRITICAL

52× loan-to-income ratio

Loan application for $2.5M on $48K income. A 52× ratio that would never pass underwriting — but passes schema.

HC-004 · WARNING

Age-inappropriate diagnosis

A 5-year-old diagnosed with age-related osteoporosis (M81.0). An adult-only ICD-10 code. Would cause claim denial.

03 / Features

Everything you need to validate LLM outputs

From a single API call to batch drift-monitored pipelines — with RAG-enhanced explanations that cite the actual regulations.

Validation Pipeline

Four-stage pipeline: JSON Schema Draft 7 structural check → 10 cross-field semantic rules → severity-weighted confidence scoring → trusted/flagged/quarantined routing. Under 1ms per record.

FastAPI 10 rules 2 domains ~3,800 rec/s

RAG-Enhanced Explanations

FAISS vector store over 11 clinical/financial reference documents. Retrieves the 3 most relevant chunks and calls Claude to generate grounded explanations citing CMS, HL7 FHIR, CFPB ATR, ICD-10 by section number.

FAISS all-MiniLM-L6-v2 claude-opus-4-5 6/6 quality score

Batch Drift Detection

Population-level shift monitoring across four signals. Builds statistical baselines per domain, then compares incoming batches — alerting when numeric distributions shift, categorical PSI exceeds 0.20, or violation rates spike.

z-score PSI null-rate violation-rate

Synthetic Dataset Generator

LLM-powered pipeline that generates 300 labeled records per domain (40% valid, 40% invalid with verified single-rule violations, 20% edge cases) with structural and semantic quality gates. Every invalid record confirmed before saving.

300 records/domain 5 rules × 24 each Quality gated

10 Semantic Rules — 2 Domains

Each rule is registered via a decorator, evaluated per record, and contributes to the confidence score based on severity.

06 / Roadmap

Future work

The current system demonstrates the core validation pipeline. Several high-impact extensions are scoped and ready to implement.

01 /

Scale to 600-record dataset

Generate the full 300-record dataset per domain using the scaffolded pipeline. Add API key to .env and run ./generate_dataset.sh to produce statistically significant evaluation results.

02 /

Expand to 3+ domains

Add insurance claims, electronic prescriptions, and financial derivatives records. The rule-registry decorator pattern makes new domains addable in <100 lines of Python.

03 /

Active learning loop

Surface borderline records (confidence 0.75–0.85) to human reviewers. Feed corrections back to retrain rule thresholds and improve edge-case handling over time.

04 /

LLM-generated rule discovery

Use Claude to analyze historical violation patterns and propose new semantic rules. Human-in-the-loop approval before rules go live, with A/B testing of rule thresholds.

05 /

Real-time streaming validation

WebSocket endpoint for streaming validation of records as they're generated. Sub-5ms end-to-end with per-token confidence scoring for partial records.

06 /

Multi-model RAG evaluation

Systematic comparison of RAG explanation quality across Claude, GPT-4o, and Gemini. Add an LLM-as-judge scorer for explanation quality beyond the 6-criterion binary rubric.
